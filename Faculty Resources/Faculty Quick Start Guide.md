# Faculty Quick Start Guide

Use this guide to create a new DES Engineering Challenge from scratch.

## 1. Choose the Engineering Topic

Select a syllabus concept that benefits from design judgement, verification, comparison, or failure analysis.

Examples:

- Verify a shaft, bracket, lever, spring, bearing, weld, or joint.
- Compare material or dimension choices.
- Diagnose why a component may fail.
- Recommend a safe design change.

## 2. Write the Industry Scenario

Create a short situation that explains why the problem matters.

Include:

- Product or system
- Stakeholder
- Operating condition
- Constraint or risk
- Required engineering decision

## 3. Complete Metadata

Use the metadata specification before writing the full challenge. Fill all required fields, including CO, PO, PSO, WK, Bloom, CCE marks, version, author, reviewer, and approval status.

## 4. Draft the Project Charter

Use the Project Charter template. Define:

- Problem statement
- Objectives
- Constraints
- Assumptions
- Student deliverables
- Success criteria

## 5. Build the Learning Path

Write activities in order:

1. Understand the system.
2. Identify inputs and assumptions.
3. Apply engineering science.
4. Use the interactive component.
5. Interpret results.
6. Make a decision.
7. Document evidence.

## 6. Add Student Support

Prepare:

- Engineering background
- Engineering tips
- Common mistakes
- Think Like an Engineer prompts
- Reflection prompts

## 7. Create the Assessment Rubric

Assign CCE marks to observable evidence. Include technical accuracy, method, assumptions, interpretation, documentation, and reflection.

## 8. Prepare Faculty Notes

Add expected misconceptions, facilitation guidance, estimated timing, alternate discussion prompts, and review notes.

## 9. Review and Pilot

Ask another faculty member to review the challenge. Then run a small student pilot and record observations before release.

## 10. Release

Release only when:

- Metadata is complete.
- Rubric is approved.
- Student instructions are clear.
- Technical content is checked.
- Pilot revisions are complete.
- Approval status is `Approved`.

## Authoring Boundary

Do not edit DES software. Do not modify platform architecture, UI, JavaScript framework, challenge runner, submission engine, Google Sheets integration, CSS, JSON schema, HTML, namespaces, or folder structure.
